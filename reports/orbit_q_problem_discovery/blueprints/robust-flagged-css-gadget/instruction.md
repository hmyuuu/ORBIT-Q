# Problem 120: robust flagged CSS gadget and recovery synthesis

For each supplied, qubit-scrambled Steane logical-zero state, synthesize one
physical flagged stabilizer-measurement gadget and a deterministic Pauli-frame
recovery table.  The evaluator executes the returned interaction order and
calibrated CNOT variants; returning the identity of a stabilizer or a claimed
score is not an answer.

This is a deliberately reduced fault-tolerant building block with an ideal
encoded data input.  The returned gadget, its two ancillas, and its
measurements are under the declared single-fault model.  The trailing
full-code syndrome and the returned Pauli-frame recovery are ideal.
Consequently, passing this task does not establish a complete deterministic
preparation protocol or a threshold.

## Input

`run_solution(config)` receives `config["cases"]`.  Each case supplies:

- seven data qubits and positive-sign `x_stabilizers`, `z_stabilizers`, and
  `logical_z` for a distance-three CSS logical-zero state;
- a shuffled `check_candidates` pool.  Every record is a nonidentity positive
  X- or Z-type member of the full target-state stabilizer and has an opaque ID;
- allowed `flag_windows`, an opaque two-entry `cx_variants` library, its
  public ideal-equivalent coefficient-transform semantics and cost, and one
  nominal three-term noncommuting coherent Hamiltonian per chronological
  entangler, plus three public calibration multipliers for every data edge;
  and
- an echo-cost budget and a coherent-fidelity threshold.

Binary products are over GF(2).  Qubit zero is the most-significant
computational-basis bit.  The full target-state stabilizer is generated by the
three X rows, three Z rows, and `logical_z`, all with eigenvalue +1.

## Gadget grammar

Select one supplied check of weight four and use one fresh syndrome ancilla
and one fresh flag ancilla.  `data_order` must contain each support qubit
exactly once.  `flag_window=[a,b]`, with `a<b`, inserts the two flag
entanglers in slots `a` and `b` among the four ordered data entanglers.  A slot
is before data interaction `slot`; slot four is after all data interactions.

For a Z check:

- prepare syndrome in `|0>` and flag in `|+>`;
- use data-to-syndrome CNOTs and flag-to-syndrome CNOTs;
- measure syndrome in Z and flag in X.

For an X check:

- prepare syndrome in `|+>` and flag in `|0>`;
- use syndrome-to-data CNOTs and syndrome-to-flag CNOTs;
- measure syndrome in X and flag in Z.

The chronological entangler list has length six.  Assign one supplied opaque
`variant_id` to each entry.  Both variants have ideal action CNOT.  In the
coherent scenario scorer they transform the three coefficients of the
calibrated post-CNOT Hamiltonian as declared.  Its Pauli terms do not all
commute, so it is not one effective Pauli rotation.  The dressing never
changes the Clifford propagation used by the separate one-fault proof.
Every two-character Pauli label is ordered `(control, target)`: for example,
`ZX` means Z on that CNOT's control and X on its target.

## Exact one-fault requirement

The evaluator independently enumerates:

1. X, Y, and Z immediately after preparation of either ancilla;
2. all 15 nonidentity two-qubit Paulis immediately after every one of the six
   atomic CNOT variants; and
3. one flip of either reported ancilla measurement bit.

It propagates signed Hermitian Paulis through the actual returned Clifford
order.  In addition to recovery correctness, the gadget must satisfy this
reduced task's **target-state flag-safety** condition: every branch whose raw
data error has target-state-stabilizer coset weight greater than one must
report flag bit one.  Because this quotient includes the declared logical-Z
state generator, it is not an arbitrary-logical-data flag guarantee.
An observation is exactly

```text
(check bit, flag bit, three X-check syndrome bits, three Z-check syndrome bits).
```

Every fault sharing an observation must use the same returned recovery.  For
each such fault, final error times recovery must be equivalent modulo the
positive signed target-state stabilizer to a Pauli of weight at most one;
global error phase is ignored only for this coset-weight test.  All 256
observation rows are returned in lexicographic bit order; unreachable rows
must use the identity recovery.

The evaluator also checks that the ideal gadget preserves the declared target
state and has zero check and flag outcomes.  It recomputes the echo cost and
all fault outcomes.  No output score or certificate is accepted.

## Coherent implementation score

For each verifier-only scenario, the evaluator starts with the independently
constructed Steane logical-zero state and the declared two ancilla states,
executes the actual returned gadget, and follows each ideal CNOT with

```text
exp(-i * sum_k transform(variant)[k] * theta[j][k] * edge(q)[k] * P[j][k] / 2)
```

Here `j` is the position in the six-entry chronological entangler list.  For
a data entangler on qubit `q`, `edge(q)` is
`data_edge_multipliers[q]`; for either flag entangler it is `(1,1,1)`.
`theta[j]` and `P[j]` are the scenario coefficients and three declared
ordered two-qubit Paulis at that same chronological position.
The score is explicitly the premeasurement implementation fidelity: the
squared overlap with the ideal final data-plus-ancilla state before ancilla
readout or recovery.  Decoder correctness is certified separately by the
exhaustive Pauli one-fault oracle.  Every hidden scenario must clear
`coherent_fidelity_floor`.  The public nominal Hamiltonians are the
solver-visible calibration objective; verifier-only perturbations are not
shown.  The solution runs in a spawned child that receives only the public
config.  After that child exits, the hidden scorer runs in the trusted parent
verifier process.

The noisy circuit-state evolution used to choose the returned check, order,
window, and variants must use TensorCircuit-NG.  NumPy may be used for GF(2)
bookkeeping, finite search, and formatting, but not as a replacement quantum
state simulator.

Return exactly:

            "case_id": str,
            "gadget": {

Exact built-in list/dict/string/integer types are required; booleans are not
integers here.  Extra fields, coercible strings, non-finite values, duplicate
rows, omitted rows, or reordered cases fail.
